## 课程数据要求

每门课的本地条目应包含：

- 稳定本地 ID、来源 App/内容提供者、源课程 ID、课程标题、采集日期、App 版本。
- 列表标注分钟数、实际视频时长、参考热量、难度；不可将参考热量当作个人实测。
- `description`：原文课程简介。
- `courseTypes`、`suitableFor`、`contraindications`、`preparation`、`bodyResponses`、`recommendations`。
- `sourceText`：完整原文，保留栏目/措辞便于复核；缺失项用 null/空列表并记录缺失原因，不编造。
- `actions`：阶段、顺序、动作名、次数或秒数；左右侧与重复组不应错误去重。
- `media`：真实 URL、本地文件、SHA-256、尺寸、视频/音频编码、字节数、下载和完整解码结果、标识/水印。
- `wearable`：官方页面声明的能力与 Still 实测能力分开记录。
- `review`：是否适合工位、是否需墙面/座椅/垫子、是否经人工核对；“待审”不能默认成为推荐动作。

## 已验证的资源取得方式

目标 App：`com.heytap.health`，版本 `6.9.37_a7d98c1_260920`。

1. 在用户已登录的 App 内查看指定课程，使 App 正常创建课程下载任务。
2. 只读取课程相关路径：`files/fit_course_video` 和 `databases/okdownload-breakpoint.db`。不要把账号数据库或整个健康数据目录导出。
3. 下载索引提供 `breakpoint(url, etag, parent_path, filename)` 与 `block(start_offset, content_length, current_offset)`。
4. 分块缓存可能稀疏预分配，当前进度之和不等于总长度时并不完整。最初两份缓存能截首帧但全片解码报错，已确认此限制。
5. 已观察两条 `v1.keepcdn.com` HTTPS MP4 URL，没有查询令牌；直接下载能够取得完整短视频。此结论只适用于已验证 URL，不代表所有课程公开可访问或可再分发。
6. 下载完成后必须执行完整音视频解码；记录实际字节数、哈希和 metadata，不能只判断请求成功/Content-Length。

原媒体保留 Keep 标识。自用媒体与公开 App 分发分开管理；本 Git 仓库不包含第三方 MP4、APK、原始课程下载索引、手机日志、截图或健康数据。

## 官方手表能力与接入边界

用户设备：**OPPO Watch X**，用户已确认能与官方课程连接。

课程页实际可见：

- 运动中实时心率展示。
- 运动后心率五区间分析。
- 页面称配对设备后可测量运动消耗。
- 开始训练时可提示开启设备“训练助手”；首次手机播放曾显示实时心率叠层，叠层不是媒体 MP4 的一部分。

“查看支持的设备”页面已看到 OPPO Watch S2、X3、S、X2 Mini、X2 和一加手表 2 等条目；当前可见列表并非完整兼容性清单，用户的 Watch X 支持情况以其现有官方连接为证。

0.2.0 存档时 Still 没有蓝牙连接、手表 SDK、手机伴侣或心率采集功能；0.3.0 实施见下文。拥有视频 URL 不会同时获得设备协议/会话控制能力。

## 待验证方案

优先顺序：

1. **公开支持路径**：核查 OPPO 健康开放平台是否向个人/第三方提供当前 Watch X 的实时心率和训练控制；区分历史数据授权与实时数据接口。
2. **标准 BLE**：只在用户当前设备授权范围内观察是否提供 Heart Rate Service。很多手表不持续广播标准心率，不能提前承诺 Mac 可直接连接。
3. **Android 中转**：若只能在手机上拿到数据，用局域网配对的 Android 伴侣向 Mac 发心率与训练状态，连接令牌、断线状态和结束清理需设计。应先证明能取得数据，再建立完整伴侣。
4. **独立手表应用**：仅当该型号/区域系统支持第三方开发与安装，且对应 SDK 能读取所需传感器时评估。

建议最小能力验证：同一段训练 60 秒内心率到达 Mac，断开后明确显示失联，退出时停止会话。后续再测暂停/继续/结束和运动记录；不能伪造心率或把媒体进度当传感器数据。

本轮不解绑手表、不清除配对、不安装证书、不关闭 TLS 校验。无法确认的私有协议只记录为待研究。

## 0.3.0 实施（2026-10-29）

### Mac 课程

已实现“休息课程”导航、四门本地档案列表、AVPlayer 本地播放、准备/反应/建议、适用说明与来源、动作顺序。缺失视频保持“视频待导入”，缺失次数显示“待补齐”，原页面未给出的禁忌不被填成“无”。原视频标识保留。

课程文件夹通过界面导入，按原始 JSON 保存到 `~/Library/Application Support/Still/Courses/`，视频在同一目录。导入验证 schema、重复 ID/动作编号、文件路径边界和可用 SHA-256；临时目录完整复制后原子替换。视频加载再检查可播放性和时长。哈希验证不代替新素材的全片解码：仍按上文验证流程采集。

跟练使用独立 guided-rest 分支：连续播放进度推动休息，暂停不推进，睡眠/锁屏信号暂停视频，跳跃或大于 3 秒的采样间隔不补记。只有播放结束且累计连续播放覆盖视频才记完成；退出/提前结束记中断。不会更改用户的默认休息分钟数。课程进度不是运动完成度/医学测量；参考热量也不是个人实测。

### 手表方案：Still Link → BLE → Mac

实现自有原生 Java Android 伴侣 `watch-companion/`（最低 Android 8），标准 SensorManager 心率 + BLE 外围设备；Mac 用 CoreBluetooth。构建及安装说明见 [Still Link](../watch-companion/README.md)。

实现的连接能力：
- 扫描 15 秒、人工选择设备、连接/订阅超时、断开清理；10 秒无真实采样清空心率。
- 标准 `180D / 2A37` 心率；支持 UINT8/UINT16、接触标志和可选字段校验。
- 独立 Still GATT 服务同步课程名、剩余时间、播放状态；手表发暂停/继续/结束。
- 加密属性与绑定设备限定；当前会话短 ID 拒绝旧控制指令；每 1–2 秒心跳，10 秒过期停用手表控制。
- 无模拟心率、无云服务、不读官方账号、不写 OPPO 健康训练记录；手表断线停止服务与传感器，未连接 2 分钟自动停止。

验证边界：**两端代码和 APK 已构建；尚未安装在用户的 Watch X，未收到该表心率，也未验证双向控制。** 仍须真机检查传感器、加密配对/订阅、ColorOS 后台限制、圆屏布局和功耗。不能把这个实现描述为“已连上 Watch X”。

当前 ADB 只看到魅族手机，手机蓝牙关闭且锁屏，课程采集暂未继续；该手机蓝牙配置未见命名配对项。ADB mDNS 没有发现手表无线调试服务。下一步需要手表开启无线调试，并使用手表显示的实际连接地址/端口；如需配对，用户提供/输入当次配对码。不解绑现有官方配对。

## 0.3.2 视频与图片持久缓存

首次直接在线播放，并在后台完整缓存，不必等待整段下载。缓存完成不重启或切换正在播放的视频，下载失败可继续观看并单独重试；后续打开或应用重启后，优先从`Still/MediaCache/Videos`播放本地MP4。URL+预期摘要决定版本，不自动按时间/容量清除。课程列表可查看大小和清理视频缓存；视频清理保留课程目录、图片及使用记录。

缓存下载进行HTTP完整响应/字节数、可选SHA256与AVFoundation可播放性校验，再原子提交；中断不记成功，目前不支持断点续传。封面/动作图片保存在`MediaCache/Images`，跨重启复用。

52项自动测试通过；真实视频验证首次原生下载46.4MB，重启缓存实例且禁用网络传输后本地播放6秒通过。独立真实AVPlayer测试同时验证：后台缓存被阻塞时仍可在线播放6秒，随后缓存完成不重置播放/休息会话。初次播放流与缓存传输为独立连接，可能增加首轮流量；不宣称单请求分块复用。

无动作课程隐藏动作栏、视频和介绍占满内容宽度。有动作课程保留原分栏。15门完整播放未逐一验收。

训练布局最终验收：标题固定，左侧动作与右侧视频/介绍为两个独立滚动区域，左栏随可用窗口高度布局，没有固定高度遮挡。滚右侧不动左侧、滚左侧不动右侧，眼部课最后“闭眼冥想20秒”完整可见。无动作课仍隐藏整个左栏。产品导入入口已撤下，缓存菜单靠右，内部目录导入验证仍保留。另已修复源栏目标题带冒号导致的字段遗漏，本机课程原文保持不变。

## 0.3.3 提醒中的课程推荐

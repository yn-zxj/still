## 产品与明确偏好

- 原生 macOS 用眼监控与休息提醒，替代个人订阅软件的核心功能。
- 中文显示名：息间；英文项目名：Still。用户指的是工程/目录用英文，不要求删除中文名。
- 重视 UI 美观、留白、图标与文字间距、较易读的字号和动效。避免重复口号、无用说明。
- 增加休息期间的工位活动：肩颈放松、头前倾相关练习、手腕/手指放松、眼部休息等。
- 课程素材希望风格统一；接受中文真人视频；当前明确用于个人使用。
- 用户手表型号：**OPPO Watch X**。用户确认官方 OPPO 健康课程支持连接该表；尚无 Still 接入验证。
- 用户已要求 GitHub 私有备份，公开与商用分发未获授权。

## 源码与构建边界

仓库根是 `Still/`，不将上层调研工作区整体初始化为 Git。原工作区的 `work/`、旁边的应用/ZIP 和私有媒体均在仓库之外。

```
Sources/StillCore/   引擎、模型、持久化
Sources/Still/       macOS 界面、系统集成与提醒
Tests/StillCoreTests/
Resources/          自有图标与附许可证的 Lucide SVG
scripts/            构建、测试、图标生成
docs/               本项目档案
```

默认构建缓存为 `.build/`，应用输出为 `dist/息间.app`，两者忽略提交。支持 `STILL_BUILD_DIR` / `STILL_APP_DIR` 覆盖。本机原有应用仍在上层 `Still-macOS/`，不自动替换正在运行的副本。

构建目标 macOS 13+，当前本机测试框架需要 macOS 14+。本机为 Apple Silicon / Swift 6.4；构建使用已安装 Command Line Tools。产物为本地临时签名，尚无 Developer ID 签名、公证、Intel 构建或公开版本发布。

## 课程研究重要结论

详见 [课程与手表研究](COURSES_AND_WATCH.md)。

1. 最初开源健身数据集的“代码许可”与“媒体许可”不同，不能整体作为免费素材使用。
2. Feeel 为步骤式动画，RepDB 免费层为静态图；Pexels 有统一系列但与用户偏好不完全吻合。
3. OPPO 健康至少部分课程使用 Keep 视频。实际见到白底统一演示、中文动作名、次数/秒数、Keep 标识。
4. Root 手机可读 `files/fit_course_video` 以及课程下载索引。视频缓存为分块下载、预分配长度，单看文件大小或首帧不能确认完整性。
5. `okdownload-breakpoint.db` 保存下载 URL、ETag 和分块进度；从已观察课程记录获取 URL 后直接下载成功。
6. 已完整验证 172.013 秒和 769.313 秒两份 1920×1080、H.264 + AAC 视频：直接 URL 下载后全片音视频解码均通过。短片已匹配“3 分钟肩颈舒缓”，长片仍待课名核对。最终以本机验证清单为准。
7. 已将 4 门课的原文简介和相关栏目存为本机 `courses.json` 与 `课程档案.md`，位于仓库外的 `private-exercise-samples/`。肩颈短课 6 个动作、眼部课 7 个动作完整采集；手指课动作表仅部分采集，头前倾动作表待采集。眼部课页面没有列出禁忌栏，保存为 null，不能解释为没有禁忌。

## 本机设备操作记录

- 首台非 Root 手机仅能访问外部文件；私有缓存权限不足。试播产生了测试训练记录，未清理即切换设备，需用户确认后仅清理测试记录。首次录屏仅验证技术可行，带心率叠层、无音轨，不作为课程成品。
- 第二台为用户已 Root 的魅族手机，Magisk 30.4、Zygisk 已启用。用户授权隐藏 OPPO 健康的 Root；加入包 `com.heytap.health` 及 `:transport`、`:SportDaemonService` 到 DenyList 并开启执行。只观察到后续未弹 Root 风险提示，不能保证所有检测场景。
- 登录“网络异常”的实因：Systemless Hosts 将 `client-uc.heytapmobi.com` 指向 `127.0.0.1`。已备份并只删除这一条规则；DNS 恢复，用户确认登录成功。原始备份只在本机，不上传。
- 不修改系统签名、关闭 TLS 验证、清空 App 数据或重新绑定手表。

## 产品与明确偏好

- 原生 macOS 用眼监控与休息提醒，替代个人订阅软件的核心功能。
- 中文显示名：息间；英文项目名：Still。用户指的是工程/目录用英文，不要求删除中文名。
- 重视 UI 美观、留白、图标与文字间距、较易读的字号和动效。避免重复口号、无用说明。
- 增加休息期间的工位活动：肩颈放松、头前倾相关练习、手腕/手指放松、眼部休息等。
- 课程素材希望风格统一；接受中文真人视频；当前明确用于个人使用。
- 用户手表型号：**OPPO Watch X**。用户确认官方 OPPO 健康课程支持连接该表；尚无 Still 接入验证。
- 用户已明确授权将 GitHub 源码仓库转为公开，用于源码审查和匿名 Release 更新；公开仓库不附带第三方课程媒体或用户数据。
- 界面验收使用用户当前运行的普通应用；不要每次另建预览应用。只有需要隔离破坏性数据时才使用独立体验实例。
- 菜单栏只显示状态图标与疲劳百分比，不显示倒计时；设置页不再提供两个菜单栏文本开关。

## 源码与构建边界

仓库根是 `Still/`，不将上层调研工作区整体初始化为 Git。原工作区的 `work/`、旁边的应用/ZIP 和私有媒体均在仓库之外。

```
Sources/StillCore/   引擎、模型、持久化
Sources/Still/       macOS 界面、系统集成与提醒
Tests/StillCoreTests/
Resources/          自有图标与附许可证的 Lucide SVG
scripts/            构建、测试、图标生成
docs/               本项目档案
```

默认构建缓存为 `.build/`，应用输出为 `dist/息间.app`，两者忽略提交。支持 `STILL_BUILD_DIR` / `STILL_APP_DIR` 覆盖。本机原有应用仍在上层 `Still-macOS/`，不自动替换正在运行的副本。

构建目标 macOS 13+，当前本机测试框架需要 macOS 14+。本机为 Apple Silicon / Swift 6.4；构建使用已安装 Command Line Tools。发布产物为 arm64 + x86_64 通用二进制，使用本地临时签名，尚无 Developer ID 签名或公证。此前 `v0.4.2` 虽然声明 macOS 13+，但实际只有 arm64；Intel 用户应改用 0.4.3 通用版。

GitHub Actions macOS 构建流水线位于 `.github/workflows/macos-build.yml`：在 `main` 推送、`v*` 标签、Pull Request 和手动触发时运行 151 项测试、双架构 Release 构建、切片级最低系统版本/Bundle/签名校验与 ZIP 打包。通用包随后分别在 macOS 14 Apple Silicon 和 `macos-15-intel` 原生 runner 上加载模型并执行无界面的 Bundle 启动检查；只有二者均通过，`v*` 标签才会创建或更新公开仓库的 GitHub Release。流水线产物为 ad-hoc 签名；Developer ID 签名和 Apple 公证仍未配置。

## 课程研究重要结论

详见 [课程与手表研究](COURSES_AND_WATCH.md)。

1. 最初开源健身数据集的“代码许可”与“媒体许可”不同，不能整体作为免费素材使用。
2. Feeel 为步骤式动画，RepDB 免费层为静态图；Pexels 有统一系列但与用户偏好不完全吻合。
3. OPPO 健康至少部分课程使用 Keep 视频。实际见到白底统一演示、中文动作名、次数/秒数、Keep 标识。
4. Root 手机可读 `files/fit_course_video` 以及课程下载索引。视频缓存为分块下载、预分配长度，单看文件大小或首帧不能确认完整性。
5. `okdownload-breakpoint.db` 保存下载 URL、ETag 和分块进度；从已观察课程记录获取 URL 后直接下载成功。
6. 已完整验证 172.013 秒和 769.313 秒两份 1920×1080、H.264 + AAC 视频：直接 URL 下载后全片音视频解码均通过。短片已匹配“3 分钟肩颈舒缓”，长片仍待课名核对。最终以本机验证清单为准。
7. 本轮通过官方 App 的课程目录缓存与只读详情调用匹配并取得15门选定课程；保存原文说明、阶段、重复动作及原始图片/视频地址。13门有180条动作，2门按摩课接口未给动作表；眼部课无禁忌栏，保留null。第三方课程JSON仍在仓库外。
8. 15个视频、81张不同动作图片共96个CDN地址，全部在Mac不带Cookie/Authorization/Referer/应用签名时返回200或206及有效媒体头；这证明当前可直连，不证明永久可用或授权再分发。OPPO列表匿名POST为403，Keep详情匿名GET虽200却空响应，不能作为公开API。详见 [资源接入](RESOURCE_ACCESS.md)。

### 0.4.3 Intel Mac 与 macOS 14 兼容

- 同事的 Intel Mac 打不开 0.4.2，系统提示“这台 Mac 不支持此应用程序”。复核 `Package.swift` 和 Info.plist 的部署目标本来就是 macOS 13.0，`vtool` 也显示 arm64 切片 `minos 13.0`；真正原因是公开 ZIP 内只有 arm64，缺少 x86_64，而不是 macOS 14 版本门槛过高。

# 自动使用检测

0.7.0 在内部自动融合输入与画面活动，不提供阅读/视频模式切换。

## 信号和优先级

1. 锁屏、系统/显示器睡眠、会话离开优先于所有输入与画面证据；暂停累计，并按已有休息规则恢复疲劳。无法查询状态时暂停判断，不把未知当成休息。
2. 键盘（含修饰键）、指针移动/按钮/拖动、滚轮使用独立的 Core Graphics 事件时距；过滤负数、NaN 和无穷值。
3. 用户通过系统输入监控授权后，使用 CGEvent 的 listenOnly 会话监听补充键盘活动时间，不需要修改输入的辅助功能授权。不读取事件字段，不保存事件对象、按键或输入文字；监听创建失败时明确显示降级状态，超时停用后自动重启。
4. 用户通过系统屏幕录制授权后，ScreenCaptureKit 捕获当前前台应用的可见普通窗口，自动切换窗口；不对桌面、Dock、Finder、登录窗口或息间自身启动采集。
5. 可靠的画面变化更新“最后活动时间”，与键鼠活动取最近一次，然后交给统一的空闲回溯与疲劳引擎。画面不再变化时，活动时距自然增长；不会将停止的视频永久算作正在使用。

未授权时使用基础输入时距检测；不反复弹系统请求、不静默授权。设置“自动检测”卡展示运行/未授权/降级状态与最近画面活动时间，提供授权与系统权限管理入口。授权不是模式开关；一旦授权，内部自动运行。用户可在系统设置撤销权限。

## 画面实现与隐私

使用 macOS 13 可用的 `SCContentFilter(desktopIndependentWindow:)` 和 `SCStream`。只捕获前台窗口，低分辨率 160×90、最多每秒一帧、不显示鼠标、禁用音频；没有录制输出、AVAssetWriter、文件、截图上传或 OCR。帧仅在回调内生成 64×36 灰度特征，旧特征只在内存里用于比较。

忽略窗口顶部和边缘；变化至少覆盖 45 个采样点、分布在 12 个区域中的至少 3 个，并且连续两次在 5 秒内达到条件，才认定画面活动。单次通知、闪烁光标、局部小动画不满足条件。它们是本项目保守的产品参数，非 Eye Monitor 精确阈值、非人体在场概率。

启动只预检授权。请求授权只由设置按钮触发。授权可能需要用户在系统设置确认并重新打开应用；查询或流创建失败后有明确降级状态与重试间隔。窗口切换会重置帧比较；每次异步请求有独立 generation，旧窗口/旧流的迟到回调不能继续产生活动。停止、暂停统计、休息、锁屏和退出时关闭采集；连续 12 秒没有有效帧时停止并重连，当前已确认的活动仅作为过去时间，不创造新活动。

## 无法消除的歧义

画面变化不等于有人在观看。无人视频仍可能算使用；静态阅读超过空闲阈值仍可能算离开。既不读取用户内容，也不默认开启摄像头，无法保证解决这两种歧义。后台播放、桌面动画和息间自身动画被排除，前台窗口里的大面积循环动画仍可能触发。

不读取浏览器 DOM、网址、文档内容或媒体标题，不使用私有 MediaRemote API。完整多屏/远程桌面/安全输入/不同 macOS 权限下的覆盖需要真人验证。

## 自动化和实机验证

纯引擎测试覆盖连续视频变化、静态画面不刷新活动、光标/标题栏/小范围动画/单次通知过滤、窗口/流更换、丢帧和无效采样、无输入视频持续计时后暂停，以及锁屏覆盖新鲜画面证据。模拟帧不等于授权后真实 SCStream 已验收。

本次本地测试 143 项（97 核心 + 46 资源/网络/模型）。构建、正常应用界面、系统授权和真实画面采集结果分别记在 PROJECT_STATUS.md。

参考：[Apple SCContentFilter](https://developer.apple.com/documentation/screencapturekit/sccontentfilter)、[SCStreamConfiguration](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration)。

键盘权限依据：[Apple WWDC19 Advances in macOS Security](https://developer.apple.com/videos/play/wwdc2019/701/)，只读事件监听需要输入监控授权；可修改输入的监听需要辅助功能授权。本实现只使用 listenOnly。

当前为 ad-hoc 签名，升级构建可能使系统要求重新授权；尚未配置 Developer ID 签名和公证，不保证跨版本权限自动保留。

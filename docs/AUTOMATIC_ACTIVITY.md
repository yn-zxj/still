# 自动使用检测

0.7.1 在内部自动融合输入、键盘辅助与媒体播放状态，不提供阅读/视频模式切换，也不再启动持续屏幕采集。

## 信号和优先级

1. 锁屏、系统/显示器睡眠、会话离开优先于所有输入与媒体证据；暂停累计，并按已有休息规则恢复疲劳。无法查询状态时暂停判断，不把未知当成休息。
2. 键盘（含修饰键）、指针移动/按钮/拖动、滚轮使用独立的 Core Graphics 事件时距；过滤负数、NaN 和无穷值。
3. 用户通过系统输入监控授权后，使用 CGEvent 的 listenOnly 会话监听补充键盘活动时间，不需要修改输入的辅助功能授权。不读取事件字段，不保存事件对象、按键或输入文字；监听创建失败时明确显示降级状态，超时停用后自动重启。
4. 读取默认输出设备的 `kAudioDevicePropertyDeviceIsRunningSomewhere`。音频播放时把它作为当前活动证据，停止播放后按同一空闲阈值自然衰减。
5. 所有有效信号取最近一次活动时间，再交给统一的空闲回溯与疲劳引擎。

基础键鼠检测不需要额外权限。键盘辅助需要系统输入监控授权；媒体播放检测不需要授权。设置“自动检测”卡展示键盘辅助和媒体播放的实时状态。

## 移除屏幕采集

0.7.0 build 29 曾使用 `SCStream` 持续比较前台窗口的低分辨率画面。真实使用中，macOS 会在左上角持续显示屏幕采集提示，遮挡应用窗口的关闭与缩放区域。用户明确反馈后，0.7.1 已删除 ScreenCaptureKit 依赖、持续窗口流、帧特征处理和对应授权入口。

当前应用不请求屏幕录制权限，不读取屏幕内容、窗口标题、网页地址或浏览器 DOM，不采集音频样本。正常应用实机检查中，打开息间后左上角不再出现采集提示；音频播放期间设置页显示“检测到媒体播放”。

## 无法消除的歧义

静音视频、无声动画和静态阅读超过空闲阈值后仍可能被算作离开。系统持续播放音频但无人观看时也可能延长计时。媒体播放状态只能说明输出设备正在工作，不能证明用户在观看。

## 验证

- 本地 145 项测试通过（92 核心 + 53 资源/网络/模型/布局）。
- `arm64 + x86_64` 通用构建、两个切片最低 macOS 13、严格签名与模型校验通过。
- 普通 `/Applications/息间.app` 已更新到 0.7.1 (31)，真实数据库、设置和课程保留。
- CoreAudio 属性在播放时返回运行状态；正常应用设置页同步显示“检测到媒体播放”。
- 构建二进制不再链接 ScreenCaptureKit，系统左上角采集提示已通过实机截图确认消失。

CoreAudio 参考：[kAudioDevicePropertyDeviceIsRunningSomewhere](https://developer.apple.com/documentation/coreaudio/kaudiodevicepropertydeviceisrunningsomewhere)。

键盘权限依据：[Apple WWDC19 Advances in macOS Security](https://developer.apple.com/videos/play/wwdc2019/701/)，只读事件监听需要输入监控授权；可修改输入的监听需要辅助功能授权。本实现只使用 listenOnly。

当前为 ad-hoc 签名，升级构建可能使系统要求重新授权；尚未配置 Developer ID 签名和公证，不保证跨版本权限自动保留。

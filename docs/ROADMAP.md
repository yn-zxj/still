# 息间功能方向

参考 Weft 暴露出的产品原则，息间优先扩展与用眼、久坐、休息和本地时间回顾直接相关的部分。

## 已在当前产品中覆盖

- **知道你何时离开**：空闲、睡眠、锁屏、暂停统计和不可观察时段都不计入使用时间；自然离开可以完成休息。
- **健康作息**：按轮次计时、疲劳值、置顶休息提醒和课程训练已经形成闭环。
- **时间去向**：前台应用、类别、切换次数、最长停留和今日时间流只保存在本机。
- **报告与导出**：应用明细、休息记录和类别分布可以回顾并导出 CSV。
- **数据归你**：应用明细、Agent 摘要均使用本地文件；设置中可清除历史，HAPI 同步直连用户自己的 Hub。
- **Agent 时间**：HAPI 会话按 ID 去重，等待区段和并行会话不会造成重复计时，其他机器上的 Agent 可以进入同一时间轴。

## 下一阶段

1. **每日与每周回顾**：给出本周与上周的休息完成率、连续久坐、应用类别变化和明确建议，避免只展示图表。
2. **透明的专注分**：公开计算公式，结合连续使用、切换频率、休息完成和离开情况；允许关闭，不把分数当作绩效证明。
3. **可编辑分类**：在现有内置类别上允许批量修正应用归类，归类变化可以回溯应用到历史记录。
4. **自定义规则**：支持按应用设置提醒密度和休息规则，为编码、阅读、会议分别选择不同轮次。

## 需要额外系统权限或谨慎评估

- **浏览器当前页面**：需要 Safari/Chrome 自动化权限；必须先解释读取范围、默认不保存标题和网址，并提供逐域排除。
- **专注时段与拦截**：涉及屏蔽或将用户拉回工作，应先完成规则、暂停和紧急退出，避免成为不可控的强制工具。
- **本地 AI 自动分类**：优先本地模型，无法识别时保留“其他”，所有 AI 结果可撤销；云端模型必须显式配置。
- **自动化入口**：可增加 `still://` 链接和 Shortcuts，用于开始休息、暂停统计、打开时间去向；写操作需要可审计和可撤销。

这张路线图用于约束后续节奏：先完善回顾与规则，再处理浏览器上下文和 AI；每项功能都要保留本地优先、暂停入口和明确的数据边界。

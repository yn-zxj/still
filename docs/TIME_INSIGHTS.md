# 时间去向：设计、口径与边界

## 参考与实现边界

时间去向的页面概念参考 [Weft](https://github.com/tiann/weft)：原生 macOS 界面、按类别展示一天的时间流，并明确“数据只留在本机”。息间没有复制 Weft 的源码或视觉资产；存储、采样、分类、统计、图表和动效均在 Still/息间自己的 SwiftUI 与 StillCore 架构中实现。

Weft 会记录窗口标题并在获得额外权限后识别浏览器页面。息间这一版刻意缩小范围：只记录前台应用的本地化名称、Bundle Identifier、粗略类别和停留时段。这样不申请辅助功能权限，也不读取窗口标题、网页地址、截图、输入内容或媒体画面。

## 数据从哪里来

`SystemActivityMonitor` 延续息间原有的一秒采样，在“时间去向”开启时读取 `NSWorkspace.shared.frontmostApplication`。`UsageEngine` 只有在原有规则认定这段时间应当计时时，才把同一秒写入应用停留段：

- 活动估算模式下，达到键鼠空闲阈值后停止计时，并按原有规则回溯最后输入时间。
- 持续阅读模式下，按息间的阅读规则继续计时。
- 屏幕睡眠、系统睡眠、锁屏、会话切出、手动暂停统计和休息期间不产生新的应用时间。
- 前台应用到后台应用的切换会结束旧段；相邻且不足一秒的同一应用记录会合并。

因此“应用时间”是前台停留时间，不等于 CPU 使用时间，也不知道用户是在看文档、写代码还是发呆。息间自身在前台时，同样会作为前台应用计入。

## 页面指标

- **应用明细覆盖**：有应用明细的时长除以息间同一范围内的总计时。低覆盖率通常意味着当时没有权限以外的问题、应用标识不可用、旧版本没有该功能，或采样被原有空闲/暂停规则排除。
- **类别构成**：按内置 Bundle Identifier/名称规则归入开发、沟通、效率、浏览、设计、媒体、学习、工具和其他类别。分类是粗略启发式，当前不支持用户在界面内改类别。
- **应用切换**：连续应用段之间发生应用变化时计数；段间隔超过 90 秒不视为一次直接切换。
- **每小时切换**：只有累计应用时间达到 10 分钟才展示，避免极短样本产生夸张频率。
- **最长停留**：连续处于同一应用的最长合并时长，不表示专注质量或没有切换窗口。
- **时间流**：今天从左到当前时刻展示类别段，尚未发生的时段不画；应用与 Agent 可并列显示两条时间轨。7/28 天按日堆叠各类别分钟数。

## 存储与删除

- 应用明细与原有使用/休息记录保存在 `~/Library/Application Support/Still/usage.sqlite`。
- 约每 20 秒及发生状态变化时写入。0.5.0 首次启动会通过 Core Data 轻量迁移新增应用明细实体。
- 关闭“时间去向”只停止后续记录，现有明细保留；再次开启后继续积累。
- 设置页“清除明细”只删除应用名称、标识、类别和停留时段，不删除总使用时长与休息记录；已通过重新打开数据库的自动化测试确认删除不会在重启后恢复。
- CSV 导出包含应用行及应用名称、标识和类别。清除后重新导出不会包含已删除的应用行。

应用历史不会自动过期或上传。当前版本没有账号、分析服务、云同步或远程模型。远程课程媒体是独立功能，与时间去向无关。

## Agent 时间与 HAPI

Agent 时间参考 [Weft](https://github.com/tiann/weft) 的 HAPI 接入方式。协议标识为 `hapi.activity.v1`，应用先执行 `hapi --version`，仅接受 0.30.0 及以上版本，再执行：

```text
hapi usage --json --since <milliseconds> --until <milliseconds>
```

报告中的 `localMachineId`、`sessions[].machineId`、`host` 与 `machineName` 用于区分本机及远程机器；`turns` 表示 Agent 工作时段，达到 5 秒的 `waits` 按实际等待区段从工作中扣除，极短的调度抖动不单独扣除。会话唯一键为 `hapi:<session.id>`，因此同一报告重复出现、定时同步重复拉取或本机已有会话都不会重复计时。

- “Agent 墙钟时间”对全部工作区段取并集；并行运行的多个 Agent 不会把一小时夸大成一小时以上。
- “会话工作时长”逐会话求和，用来观察多个 Agent 并行时的总工作量。
- 本机会话显示“这台 Mac”，其他机器优先显示 HAPI 报告的 `machineName`，缺失时显示主机名。
- 报告退出码 3 显示“尚未登录”，4 显示“HAPI Hub 需要升级”；旧版未知 `usage` 命令不会被误当成 Agent 启动。
- 自动同步间隔 5 分钟，设置页可立即同步、手动选择 `hapi` 或恢复自动查找。
- Agent 摘要单独保存在 `~/Library/Application Support/Still/AgentActivity.json`，保留 31 天、文件权限 0600。清除历史不会删除 HAPI Hub 中的原始会话。
- 本机没有可用的 `hapi` 时，设置页可从官方 GitHub Release 一键安装。安装器按芯片选择 `arm64/x64`，用官方 `checksums.txt` 校验 SHA-256，只接受单个 `hapi` 文件的安全归档，最终安装到 `~/Library/Application Support/Still/HAPI/bin/hapi`，无需管理员权限。

HAPI 只返回会话级元数据。息间不读取 Agent transcript，不保存 prompt、回复、代码、终端输出或账号凭据。同步由本机 `hapi` 直接连接用户自己的 Hub，不经过息间的服务器。0.5.1 普通应用已实际安装并验证 HAPI 0.33.3，但本机没有登录 Hub，真实 Hub 与跨机器验收仍不能由模拟报告替代。

## 已知限制

- 从 0.5.0 才开始保存应用明细，旧版数据库无法还原升级前用在了哪些应用。
- 只区分前台应用，不区分同一应用里的不同文档、项目或浏览器标签。
- 不使用辅助功能或浏览器自动化，因此无法给出网页域名、项目名或窗口标题。
- 一分钟按秒采样，系统切换事件短暂发生在一个采样间隔内时可能归到相邻应用；汇总值应以分钟级趋势理解。
- 分类为本地规则匹配，未知应用进入“其他应用”；没有使用机器学习猜测内容。
- 不提供员工监控、工时结算或生产力评分。应用在后台运行的时长不会算作前台停留。

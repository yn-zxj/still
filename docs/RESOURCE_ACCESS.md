# 课程资源接入决策

2026-10-29。用户希望息间使用自己的界面，直接使用已可访问的课程资源，不维护视频服务器。

## 当前方案

本机保存一个小型 `courses.json`，包含所选课程的来源、简介、准备、反应、建议、有序动作与HTTPS资源地址。AVPlayer直接播放远程视频，动作图片按需加载并使用缓存。已有本地文件时优先本地文件，离线导入继续可用。

不设置自建视频后台，不把第三方视频打包进应用或仓库，不把OPPO账号/Keep接入凭据写进息间。课程目录是本次本机快照，不宣称自动同步官方全部课程。

## 实际接口与验证

目标是用户手机的OPPO健康 `com.heytap.health`，版本 `6.9.37_a7d98c1_260920`。以下为实际安装包定义及本机观测，不是公开API文档。

| 层 | 观察 | 结论 |
| --- | --- | --- |
| OPPO课程总表 | `POST sport.health.heytapmobi.com/sporthealth/v5/c2s/course/queryAllCourses`；空JSON匿名请求403，`errorCode=10103`随机数或参数错误 | 不能当作匿名API；安装包有V2Signer与请求签名流程 |
| OPPO详情 | `POST .../v1/c2s/new/training/miao/queryCourseDetail`；匿名请求同为403 | 未证实匿名可用 |
| Keep详情 | `GET api.gotokeep.com/avatar-webapp/heytap/detail?courseCode=...`；接口定义含accessKey头，KeepTemp从OPPO配置加载接入信息 | Mac无鉴权请求返回200但Content-Length=0，不能把HTTP200视为拿到课程；没有提取或复用accessKey |
| 官方App只读查询 | 读取课程目录内存缓存，按用户选择的courseCode调用现有Retrofit `queryKeepCourseDetail` | 15门完整课程详情已取得，正常使用App当前网络栈；未修改TLS验证或请求签名 |
| 视频CDN | `v1.keepcdn.com` 的15个MP4地址 | Mac仅带Range请求，全部206并含MP4媒体头；不需要Cookie、Authorization、Referer或应用签名 |
| 动作图片CDN | `static1.keepcdn.com` 的81个不同图片地址 | 相同匿名范围检查全部200或206且媒体头有效 |

所有96项检查仅证明2026-10-29当前地址可访问，不证明长期稳定、整个文件无损或允许公开再分发。HTTPS是传输保护，与是否要求登录/请求签名不同。此次不抓取账号或训练记录，不调用加入课程/创建训练等写入接口。

## 数据完整性

- 用户所选15门均匹配到原始courseCode，顺序按用户清单保留。
- 13门提供180条动作，保留阶段、左右侧、次数/秒数和重复组；81张原始动作图，无截图裁剪边框。
- “上班族肩颈按摩”“上班族腰背按摩”详情没有actions字段；保留完整视频与说明，界面明确源未提供拆分。这两门的准备说明需要按摩者/被按摩者，不能默认作为独自工位活动。
- “3 分钟天鹅颈训练”源名称含3分钟，源duration=120秒，简介为减脂通用文案；原始资料保留不一致备注，不能凭标题覆盖时长或改写疗效。
- 缺失禁忌栏保留null，不能填成“无”。课程原文医学表述与热量只作为来源信息，不代表个体建议或测量结果。
- 视频实际时长由AVFoundation加载；展示的目录分钟数单独保留，跟练计时不使用标题猜测。

## 本机资料与维护

第三方资料位于仓库外 `../private-exercise-samples/remote-courses.json`；原始响应、安装包与验证清单在上层工作区 `work/oppo-health-research/`。不提交这些内容。

关键本机证据文件：`requested-15.json`、`selected-15-details.json`、`all15-anonymous-resource-check.json`、`all15-remote-probe.json`。源码仓库只记录结构、结论、验证范围和未完成项。

地址失效时明确提示，可重新导入目录或本地媒体；不能通过静默吞错或无限重试把失效伪装成可用。动态目录更新需后续另证实正式开放路径，当前不作为产品依赖。

- 远程媒体验证补充：15个MP4均可匿名读取ffprobe元数据，视频/音频轨道和实际时长已记录到本机目录。天鹅颈视频实际176.936秒，源列表duration=120秒；课程跟练使用实际媒体时长。本检查不代替15部全片解码。

## 封面资源与HTTPS规范化

15门详情的courseImage已映射为可选coverURL，并逐一匿名下载检查200及图片内容。原始动作表中有10个不同HTTP图片地址，本机目录显式改为同主机/路径的HTTPS版本前，已对这些HTTPS地址逐一验证200与JPEG头；没有放宽应用HTTPS校验。最终目录全部远程资源使用HTTPS。加上15张封面，视频/动作图/封面共111个资源当前可访问。

训练视频不固定高度：读取视频轨道naturalSize及preferredTransform，兼容横屏、竖屏与旋转素材；在本机合成素材上验证比例1.6667、0.6、0.6分别通过。远程播放使用媒体实际时长，目录分钟数仅作源信息。

## 0.3.2 缓存策略更新

首次视频可立即在线播放，同时后台获取完整MP4；后续优先使用Application Support/MediaCache内的已验证本地文件。视频缓存任务与播放器独立，完成后不重启当前视频，失败不阻塞观看，可单独重试。源地址+预期摘要决定版本；封面和动作图同样持久保存。

当前AVPlayer流和完整文件下载为独立连接，首轮可能额外耗用流量；没有实现单连接分块共享。完整缓存后下一次不再下载视频，不自建后台或账号服务。

命中缓存不访问远端，以支持离线；同一URL内容更换需要手动清理或导入新URL。未完成下载不标为命中，退出后再次打开仍需联网，暂不支持断点续传。验证是传输完整性、可选源摘要和AVFoundation轨道/时长检查，不能当成所有视频全片解码。

## 0.3.3 请求调度与失败证据

整段缓存从进入课程延后到实际开始跟练，单缓存器最多一个下载，切课取消旧未完成下载。元数据和图像请求不再被“只浏览课程”产生的全片下载队列竞争。播放器仍可直接在线使用，失败时用户可主动选择完整缓存后再播放；完整缓存继续离线复用。

头前倾视频和两张筋膜球图片当前同URL返回成功、图片可解码、AVPlayer可读取797.1秒时长；历史失败未复现。新增脱敏诊断和细分错误，不能仅凭重试恢复便断言原因为何。系统代理配置未被修改。Diagnostics日志只含主机/URL哈希/错误码，不包含路径、查询参数、账号或请求头。

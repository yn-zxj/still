# Eye Monitor 计时逻辑研究与 Still 正确性

日期：2026-10-31。目标为本机 Eye Monitor 13.1.19 (139)，不涉及订阅/授权逻辑。研究目的是独立实现使用时间判断；没有复制第三方实现代码进入 Still。

## 已确认的逻辑

| 问题 | 证据 | 能确认什么 |
| --- | --- | --- |
| 智能模式如何判断使用 | 准确性页，以及二进制智能模式说明 | 鼠标/触摸板、键盘、屏幕内容变化共同参与；输入和屏幕权限影响覆盖 |
| 是否也有持续计时 | 二进制另一模式的说明 | 存在“除锁定或休眠外持续认为正在使用”的模式；名称不同于 Still 原阅读模式。用户不希望页面提供手动模式开关；期望 Still 在内部自动判断场景，并非要求删除无输入阅读/视频的计时能力 |
| 疲劳是否医学测量 | 二进制疲劳解释 | 按配置的工作/休息时长换算进度。100 分钟工作对应每分钟约增加 1 个百分点；5 分钟休息对应每分钟减少约 20 个百分点 |
| 锁定/睡眠是否优先 | 主定时路径 `0x1000772a8–0x1000772c4` | 检查 lockState / sleepState 后跳过常规处理；屏幕检测路径 `0x10007d8a4–0x10007d8c8` 同样先检查这些状态和屏幕授权 |
| 退出锁定后如何恢复 | 解锁路径 `0x10007efd8–0x10007eff8` | 清除锁状态；另一个睡眠状态未激活时才调用统一离开时长计算，避免两类状态重叠时重复处理 |
| 恢复是否依赖逐秒 timer | `0x10007beec–0x10007bf28`、`0x10007c048–0x10007c124` | 计算保存的离开时间到当前时间的差；恢复路径含按分钟换算和下界处理。存在唤醒/解锁时补算恢复的路径 |
| 屏幕变化是否真有实现 | `0x10001d070–0x10001d0a0`、`0x10001d3e4`、`0x10007d938–0x10007d9d4` | 获取活动显示器画面、比较两帧并区分相同/不同；不能仅凭其中一次变化就证明有人正在看 |
| 是否读取了文字内容 | 屏幕比较路径 | 已检查路径比较图像与像素数据；未见此路径调用 OCR。有限路径分析不能证明整个程序无其他读取行为 |

不能确认的部分：完整采样调度、所有事件掩码、完整像素阈值及所有平台分支；长时间无人看视频的误判率；屏幕截图是否始终仅驻留内存。二进制隐私说明称仅保留最近截图且不上传，但本轮没有完整文件/网络跟踪验证这一声明。

## 用户意图澄清

用户要求的是“内部自动完成，不让用户操作模式开关”。界面保持统一自动检测；阅读/视频等无持续输入的使用场景仍应由内部信号融合覆盖。先前将此理解为删除持续计时能力过于宽泛。参考应用的另一模式属于静态分析发现，不能直接等同于 Still 应采用的自动策略。

该段最初记录 0.6.1 状态。0.7.0 build 29 曾接入前台画面变化和键盘辅助，但真实使用发现 macOS 的屏幕采集提示会持续遮挡左上角窗口控件。build 30 已移除 ScreenCaptureKit，当前改为输入、键盘辅助与音频播放状态融合，详见 AUTOMATIC_ACTIVITY.md。静音视频和无人播放仍存在歧义，不能把无输入一律当作持续使用。

## 与 Still 的差异及本轮修改

1. **息屏后的恢复**：已在本轮之前修复；有明确不可用证据才降低疲劳，检查点保留恢复锚点。未知程序缺口不当作休息；不为恢复虚增完成休息次数。
2. **状态未知与确认离开**：原先查询会话/显示器失败也返回 available=false，新增恢复逻辑会把它误当休息。本轮增加 inactivityConfirmed：查询失败、无显示器枚举结果或无法识别状态只暂停，不恢复、不累计，也不把此前的不可用证据跨过未知区间延长。
3. **输入信号细化**：原先查询任意输入事件。本轮分别查询键盘（含修饰键）、鼠标移动/点击/拖动、其他按钮和滚轮；取有效信号中最近一次输入。无效负数、NaN、无穷值不被当作刚输入或长时间离开。全部失败时停止判断。仍使用 combinedSessionState，不能承诺区分人工输入与远程/脚本合成的同类输入。
4. **屏幕变化**：0.7.0 已独立接入可授权的前台窗口低频画面对比，不照搬参考的整屏截图实现；仍需分别验证误判/漏判，不能宣称已达到 Eye Monitor 的真实准确率。

Apple 官方说明：[任意输入事件类型](https://developer.apple.com/documentation/coregraphics/event-source-token)、[会话查询可返回 NULL](https://developer.apple.com/documentation/coregraphics/cgsessioncopycurrentdictionary%28%29)、[显示器睡眠状态](https://developer.apple.com/documentation/coregraphics/cgdisplayisasleep%28_%3A%29)。任意事件 sentinel 本身是有效 API，本轮细分信号不是将其认定为 Apple API 错误。

## 屏幕辅助检测的后续设计

此前设计计划使用 ScreenCaptureKit 兼容 macOS 13。该方案已在 build 30 撤销，原因是系统采集提示持续遮挡窗口控件；当前产品不再读取屏幕内容。

锁屏、息屏和睡眠优先停止累计。音频播放状态无需屏幕权限，但不能证明用户在看；静音视频、动态壁纸、静态阅读需要单独测误判，不能把“媒体设备正在运行”当作可靠的人体在场检测。

## 验证矩阵与边界

- 自动化：键盘/鼠标/滚轮时距聚合、异常查询、未知状态不可恢复、未知区间不桥接、明确离开跨重启、系统时钟跳变、普通程序缺口、旧阅读设置迁移及历史数据保留。
- 本机只读 API 探测：键盘 3 类、鼠标 10 类、滚轮 1 类均取得有限非负时距，彼此时距不同；只查询时间，不读取按键内容。它不证明所有权限配置或远程控制工具均可靠。
- 待真人分场景验证：仅打字、仅鼠标、仅滚轮、静态阅读、视频播放、远程桌面、合盖、息屏、锁屏、真休眠、DarkWake、多屏切换及长时能耗。此次没有让用户电脑主动进入休眠，不能称为完整系统电源验收。

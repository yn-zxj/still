# 息间 0.6.0

给每一段专注，留一点余地。

原生 macOS 用眼与休息提醒工具。SwiftUI + AppKit 界面，独立 Swift 计时引擎，Core Data 本地持久化。应用主体没有第三方运行时依赖、自建账号或分析上报；选用远程课程时直接访问其媒体或网页来源。界面图标使用原生矢量绘制的 Lucide，版权许可随源码及应用附带。

已发布版本可从公开仓库的 [GitHub Releases](https://github.com/yn-zxj/still/releases) 匿名下载。附件为 Apple Silicon 与 Intel 通用构建，支持 macOS 13 及以上；使用 ad-hoc 签名，尚未通过 Apple 公证。

## 开始使用

从源码构建后，应用位于 `dist/息间.app`。关闭主窗口后仍会记录；点击菜单栏叶子图标查看面板，也可以重新打开应用回到主窗口。退出应用会停止计时。可将应用移至“应用程序”目录，再按需启用登录启动。

默认工作 45 分钟、休息 5 分钟，键鼠空闲阈值 90 秒。中文应用名为“息间”，英文工程目录及内部标识使用 Still。

- 今天：疲劳百分比、下一次休息倒计时、今日使用、完成休息、最长一轮、全天使用分布。
- 时间去向：今天/7 天/28 天的前台应用时间流、类别构成、应用排行和切换情况；通过 HAPI 汇总本机及其它机器上的 Codex、Claude Code 等 Agent 会话。时间轴固定 0–24 时，未来数据留空。
- HAPI 一键安装：从官方 GitHub Release 按芯片下载独立二进制，校验 SHA-256 后安装到用户目录，不需要 npm、Homebrew 或管理员权限。
- 休息提醒自动开始倒计时，到点自动关闭；选择跟练课程后由课程播放进度接管本次休息。
- 使用记录：真实的 7 天/28 天历史、最近休息、CSV 导出。
- 休息规则：全屏弹窗、迷你弹窗、系统通知三选一；自定义文案、今日时长显示、独立预览；三组预设和自定义时长、活动检测、空闲及重复提醒间隔。
- 偏好设置：提醒与统计分别暂停、声音、动效、Agent/HAPI 同步、隐藏 Dock 图标、可选登录启动、坐姿功能开关及 GitHub Release 检查更新。
- 坐姿关照：4 秒个人校准，头部/肩部实时关键点，本机 Lightweight OpenPose + Apple Vision，支持后台分析、暂停、顶部纯文字置顶提醒；正常前后移动保留参照。规则里的数字可原位编辑，回车或移开焦点自动保存，修改后即时生效并保留校准，支持恢复默认。默认累计 12 秒触发、展示 5 秒、冷却 60 秒；12 条吐槽和 4 条温柔提醒按动作类型轮换。
- 休息窗口：全屏或迷你倒计时、呼吸花、疲劳百分比、提前结束、延后和跳过。全屏可按 Esc 或退出按钮关闭。
- 疲劳值：显示在今日概览、菜单栏、快捷面板和休息窗口中。使用时增加、休息时减少，范围 0–100%。

菜单栏固定展示状态图标与疲劳百分比，不显示倒计时。“预览提醒”仅展示外观，不改变计时或生成休息记录。系统开启减少动态效果，或关闭应用内呼吸动效时，会停用环境动画。主窗口不在前台或不可见时暂停主卡环境动画。

## 计时口径

活动检测：短于阈值的停顿计入工作；连续空闲达到阈值后，回溯至当前活动区间内最后输入时间，撤销候选空闲。自然离开达到休息目标后重置本轮。统一根据键盘、指针和滚轮的活动时距判断使用与离开，不再提供手动阅读模式开关；查询结果未知时暂停判断，不自动算成休息。

延后和跳过不清除使用量；提前结束休息不算完成，也不重置本轮。暂停提醒仍统计，暂停统计则保留进度但不累计。疲劳值按工作目标归一化，实际休息和自然离开会逐步降低；提前结束休息后保留已恢复的进度。工作时间按单调时间差计算，超过 15 秒的未观测间隔不补算；系统/屏幕睡眠和会话切出时停止累计，并按休息时长逐步降低疲劳；明确的不可用状态会保存到检查点，重启后可继续恢复疲劳；普通退出或采样缺口不会凭空算作休息。

疲劳值是计时规则推算的进度，不代表医学测量。手动完成休息表示用户运行完倒计时；自然完成表示依据活动规则推断的离开，都不等于检测到实际起身或眼部疲劳。原始区间按本地日历聚合，CSV 使用带时区的 ISO 8601 时间戳。

## 数据位置

- 记录：`~/Library/Application Support/Still/usage.sqlite` 及其 WAL/SHM 文件。
- Agent 会话摘要：`~/Library/Application Support/Still/AgentActivity.json`，保留 31 天、权限 0600。
- 设置与检查点：UserDefaults 域 `local.still.app`。
- 状态变化、约每 20 秒和正常退出时保存。

如果磁盘无法保存，界面会显示错误并提示先导出；不会悄悄覆盖已有历史。UI 验证产生的实际使用/休息记录也会保留在本机。

## 构建与测试

构建应用需要可用的 Apple Swift 工具链与 macOS SDK；测试使用工具链自带 Swift Testing。本次环境为 Apple Silicon / macOS 27.0.1 / Swift 6.4。完整 Xcode 未接受许可，因此本次使用已配置的 Command Line Tools 构建，没有修改全局开发工具选择或代用户接受许可。

在本目录中运行：

```sh
bash scripts/build-app.sh
bash scripts/test.sh
```

脚本把编译缓存放在仓库 `.build/`，把应用写入 `dist/息间.app`；可用 `STILL_BUILD_DIR` 和 `STILL_APP_DIR` 覆盖输出路径。若全局 Xcode 尚未可用，可在命令前设置 `DEVELOPER_DIR=/Library/Developer/CommandLineTools` 使用已安装的 Command Line Tools。打开 `Package.swift` 可查看源码；也可用 Xcode 打开此 Swift Package，完整 Xcode 的许可由用户自行处理。

GitHub Actions 会在 `main` 推送、`v*` 标签、Pull Request 和手动触发时运行测试并构建 arm64 + x86_64 通用应用。通用包会分别在 macOS 14 Apple Silicon 和 Intel runner 上启动校验；只有两个架构都通过，`v*` 标签才会创建或更新 GitHub Release，并附上带版本号、Commit、架构清单和 SHA-256 的 ZIP。当前产物使用 ad-hoc 本地签名，尚未配置 Developer ID 和 Apple 公证。

版本检查直接匿名读取公开仓库的 GitHub Release，不需要账号或访问令牌；下载包需通过大小和 SHA-256 检查，再由用户解压并替换原应用。坐姿模型来源、论文对应关系、精度限制和隐私说明见 [坐姿与更新](docs/POSTURE_AND_UPDATES.md)。应用不录制、保存或上传摄像头画面；正面镜头不测量标准颅椎角或颈椎曲度。

## 时间去向

“时间去向”参考了 [Weft](https://github.com/tiann/weft) 展示一天时间流向的思路，代码和视觉均为息间的独立实现。当前版本只采样前台应用，不读取窗口标题、网页地址或屏幕内容，也不需要辅助功能权限。与总使用时长的差值会明确显示为应用明细覆盖率，不会把未识别时间伪装成某个应用。

应用明细从 0.5.0 开始积累，升级前的使用记录仍保留在“使用记录”中，但不会伪造历史应用名称。暂停统计、屏幕睡眠和无活动状态遵循原有计时口径。类别由内置规则按应用名称与标识粗略归类，未知应用会进入“其他应用”；这些数据用于个人回顾，不是员工监控或精确工时证明。

Agent 时间同样参考 Weft 的 HAPI 接入方式，使用 `hapi.activity.v1`、`hapi usage --json` 和 HAPI 0.30 的最低版本门槛。应用只保存会话标题、项目路径、Agent 类型、机器名称和工作时段，不保存 prompt、回复或代码内容。同步由本机 `hapi` 直接连接用户配置的 HAPI Hub；相同 `session.id` 重复同步会合并，等待用户回复的 `waits` 会从工作时间扣除，本机已读过且由 HAPI 返回的会话也统一进入时间去向。

普通应用已从“未找到 hapi”状态实际点击安装 0.33.3，安装文件通过官方 SHA-256 校验并可运行，随后正确进入“HAPI 尚未登录”。模拟 CLI 覆盖成功同步、远端机器、重复会话、等待扣除、退出码和持久化。真实 Hub 登录与跨机器会话仍需用户按 HAPI 官方流程配置后验收。

隐私边界、统计口径与已知限制见 [时间去向](docs/TIME_INSIGHTS.md)。

## 当前范围和待验收项

- 本地编译产物为 arm64 + x86_64 通用二进制，使用临时本地签名；尚未做 Developer ID 签名、公证或 App Store 发布。部署目标为 macOS 13；测试框架本身需要 macOS 14 及以上。
- 已实现全屏、迷你窗和通知提醒；全屏会为当前连接的每块屏幕建立窗口，并在显示器变化时更新。不同多屏组合、其他应用全屏、屏幕热插拔仍需真机验收。iCloud/手机同步、旧 Eye Monitor CSV 导入尚未实现。
- 迷你窗使用浮窗层级；全屏提醒使用覆盖窗口并提供退出操作。不承诺覆盖系统安全界面或所有其他应用的独占全屏内容。
- 公开的系统睡眠、屏幕睡眠和会话切换通知已接入；锁屏额外使用未文档化的 `com.apple.screenIsLocked/Unlocked` 分布式通知作为补充。它不是跨版本保证，仍需验证“锁屏但屏幕保持点亮”等场景。手动暂停统计也可用。
- 默认不请求键盘监听、摄像头或屏幕录制权限，只查询系统输入空闲时间；仅启用坐姿关照时才请求摄像头。纯键盘输入、远程输入、不同权限环境仍需真实使用验收，不能用自动化 AX 点击代替这一测试。
- 系统通知需在应用内主动允许，未授权时会显示明确提示；通知提供开始休息和延后操作，预览通知不会产生休息记录。已验证未授权提示；成功送达与通知操作回调尚未实机验收。开发验证未替用户授予权限或开启登录启动。
- 支持浅色、深色与跟随系统三种外观；主窗口、菜单栏面板、提醒窗口和课程页面共用动态配色。动效已支持系统减少动态效果。
- 快捷面板点击应用外部会自动收起；隐藏 Dock 图标后菜单栏入口、计时和提醒继续工作，也可从设置立即恢复 Dock 图标。
- 后续应进行真实 45 分钟周期、多屏、合盖/唤醒、锁屏和长时能耗验收。

应用支持 `--ui-test`（内存数据且不恢复真实设置）、`--short-rest`（仅在 UI 测试模式下把手动休息缩短到 5 秒）和 `--preview-rest`（打开外观预览）等开发参数。默认启动不会使用它们。

## 休息课程（0.6.0）

“休息课程”读取本机课程目录；视频、动作图片支持HTTPS远程地址，也兼容已有的同目录本地文件。支持在课程库添加视频、导入/导出 JSON 并编辑可选说明和动作。跟练进度与休息同步，支持暂停/继续/结束；原始课程简介、准备事项、反应、建议与动作顺序保留。课程媒体不随源码分发。

进入休息课程先显示原始封面卡片，点击后左侧为分阶段动作列表，右侧视频按素材实际比例显示；两栏独立滚动，标题固定，动作栏高度随窗口变化；页面及动作列表隐藏滚动指示器，仍可正常滚动。动作列表支持课程自带的图片预览。手表连接已按用户要求暂缓并从当前应用撤下，原型仅保留在 `experiments/watch/` 和 `watch-companion/`，不属于当前可用功能。

持续状态：[项目档案](docs/PROJECT_STATUS.md) · [课程与手表](docs/COURSES_AND_WATCH.md)。


普通媒体直链首次跟练可直接在线播放，同时在后台缓存，播放器下方显示缓存状态；不需要等待整段下载。只浏览课程不会下载整段视频，切换课程会取消旧课程未完成的缓存。完整缓存校验通过后，以后和重启应用后都优先使用本机文件，无需再下载。封面与动作图片也会在首次加载后保留到本机。缓存位于 `~/Library/Application Support/Still/MediaCache/`，课程目录重新导入不会删除它，应用不会自动淘汰视频。课程列表右上角显示视频缓存大小，可清理视频缓存；清理不会删除课程目录、导入的原视频或使用记录。下载失败/中断的文件不会被标为已缓存，目前中断后重试会重新下载。

没有动作拆分的课程隐藏整个动作栏，视频及下方介绍占满内容区。


迷你与全屏提醒使用高窗口层级，跨Space和全屏辅助显示；锁屏、安全界面及系统通知的展示由macOS控制。提醒窗增加短课程推荐及“换一个”，优先当日未推荐过的课程，候选用完后循环并尽量避免连续相同。可直接在提醒窗里播放、暂停、结束课程；预览跟练不写入正式休息记录。

资源失败会显示具体原因，动作图片可单独重试；视频在线播放失败也可选择“缓存后再播放”。脱敏错误记录在Application Support/Still/Diagnostics中，仅含资源主机/哈希与错误码，不含URL路径、查询参数或账号信息。

常规本机验收直接更新并重开 `dist/息间.app` 普通应用，保留已有课程、设置与使用记录；只有隔离破坏性测试才另建体验实例。提醒跟练的进度与缓存状态固定在底部，视频区域滚动不会再改变播放进度。

课程现为可选功能，默认关闭。用户可自行导入 JSON、本地视频或自动识别的视频/网页链接，应用不附带第三方课程。参见 [课程库说明](docs/COURSE_LIBRARY.md)。

链接识别可自动填写标题、封面、简介、时长；支持在添加页安装/更新可选 yt-dlp 通用组件，B站使用附 MIT 许可的 media-parser 流程适配。只使用完整音画流；分离流或失败保留网页播放。解析出的临时地址播放前会刷新，此类来源当前不自动缓存。详情及实测边界见 [课程库说明](docs/COURSE_LIBRARY.md)。

计时正确性研究与验证边界见 [Eye Monitor 逻辑对照](docs/EYE_MONITOR_ACCURACY.md)。当前尚未实现屏幕画面变化辅助，看视频/静态阅读的覆盖仍有限。
